# הבודקת — מערכת ניהול ואימות שאלות טריוויה

מערכת ווב לניהול מחסן שאלות לשעשועון טלוויזיה: ייבוא שאלות מגוגל שיט, אימות
אוטומטי של התשובה הנכונה מול **שני מקורות מוסמכים** (לא ויקיפדיה), בניית "תיק
תשובה" עם לינקים והסברים, אישור ידני ע"י בודק, ושיבוץ למתמודדים.

## מסמכים

| מסמך | מה בו |
|---|---|
| [`docs/SPEC.md`](docs/SPEC.md) | אפיון מלא: סכמת DB, מכונת מצבים, מדיניות מקורות מוסמכים, מנוע האימות, הרשאות, מסכים |
| [`docs/LOVABLE_PROMPTS.md`](docs/LOVABLE_PROMPTS.md) | 8 פרומפטים ללאבאבל, לפי הסדר, לבניית המערכת |

## איך בונים

1. פתח פרויקט חדש בלאבאבל והעתק את הפרומפטים מ-`docs/LOVABLE_PROMPTS.md`, אחד
   בכל פעם, בסדר הכתוב. בדוק בפריוויו בין שלב לשלב.
2. אשר חיבור Supabase (שלב 0) והפעלת Lovable AI (שלב 3).
3. בסיום שלב 7 — חבר את פרויקט לאבאבל לריפו הזה (GitHub → Connect).
4. משם ממשיכים לחדד את הקוד, ובמיוחד את איכות מנוע האימות — `docs/SPEC.md` §4.6.

## עיקרי המערכת

- **סיבובים:** 1-3 → 4 תשובות, 4-6 → 3 תשובות, 7 → 2 תשובות.
- **שיוך:** לכל שאלה יש כותב.
- **אימות:** שני מקורות בלתי תלויים מדומיינים שונים. ויקיפדיה, ויקיז, בלוגים,
  פורומים ואתרי טריוויה פסולים. השרת מאמת שהלינקים קיימים — המודל לא יכול
  להמציא מקורות.
- **פסילה מנומקת:** תשובה שגויה או לא מדויקת, או יותר מתשובה נכונה אחת, פוסלת
  את השאלה עם הסבר.
- **ניסוח:** שאלה לא ברורה מקבלת הצעת ניסוח מדויק, והכותב בוחר לאשר או לסמן
  לחשיבה מחדש.
- **קושי:** 1 קל … 5 קשה מאוד.
- **שיבוץ:** אחרי שיבוץ למתמודד אין ביטול — רק העברה, עם נימוק ובשרשרת מתועדת.
- **תפקידים:** מנהל (הכל), בודק (בודק ומאשר ידנית), כותב שאלות (מעלה, משייך,
  בודק בדיקה ראשונה, משכתב).
